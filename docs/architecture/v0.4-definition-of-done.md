# UnitAtlas v0.4 Factory Pilot & AIDC — Definition of Done

## Boundary

v0.4 connects physical Data Matrix/SSCC scans and label printing to the existing UnitAtlas ledgers and integration runtime. The server remains the only source of truth. Capture devices keep a disposable cache and an idempotent command queue; they never silently overwrite server state.

Out of scope: direct IS MPT, RFID, Kafka, Redis, Kubernetes, SAP, EPCIS XML/query/subscriptions, IoT, AI, blockchain and WMS optimization. The first pilot remains single-replica.

## Release gates

| Gate | Required evidence |
| --- | --- |
| Product arrives from the selected 1C pilot profile | automated contract/integration test |
| Production batch creates 100 Units | automated end-to-end test |
| 100 unit labels and one logistics label are generated | print contract and payload tests |
| Printed codes are verified by scan | production capture test |
| Offline Unit → Box → Pallet commands replay after reconnect | deterministic sync test |
| Replay creates no duplicate event and loses no accepted scan | idempotency assertions |
| Conflicting aggregation returns `CHILD_ALREADY_AGGREGATED` and preserves server state | conflict test |
| Shipment reaches Outbox and receives 1C acknowledgement | integration test |
| EPCIS export and public/internal passports match the canonical ledgers | existing and new regression tests |
| Tenant composite FKs, FORCE RLS, audit and append-only invariants stay enforced | database CI checks |
| Access session renews without exposing tokens to browser JavaScript | BFF auth test |
| Backup from all v0.4 migrations restores into a fresh database | dated rehearsal evidence in the factory runbook |
| 1,000 sequential scans are measured | report success, recognition errors, duplicates, sync retries, p50 and p95 |

`v0.4.0` may be tagged only from the verified merge commit after every gate above has evidence. Physical-device and printer evidence cannot be replaced by a simulator claim; if pilot hardware or credentials are unavailable, the release remains a release candidate.

Selected software contract: `ONEC_UPP_KZ_1_3_HTTP_JSON_V1` for 1C:UPP Kazakhstan 1.3. The automated `ConcretePilotProfileTests` route creates 100 unit labels and one pallet label, rejects commissioning before `PRINTED`, confirms 100 scans through `/capture/production`, suppresses a repeated scan and completes packing/shipment/EPCIS; it remains software evidence only. OIDC renewal has an automated server-side refresh test, and the 2026-08-16 development backup/restore rehearsal is recorded in the factory runbook. Real 1C extension/database certification and physical printing/scanning remain separate gates.

## Rollback

Application rollback uses the previous immutable image SHA. Schema rollback is allowed only from reviewed SQL after backup; if it risks data loss, restore into a new database and switch the connection string. Capture clients retain unsent commands until the server acknowledges them.
