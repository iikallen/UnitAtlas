# ADR 0001: модульный монолит для v0.1

- Статус: принят
- Дата: 2026-08-15

## Контекст

Первый demo-срез держал HTTP, EF Core и доменные сущности в одном API-проекте. Это ускорило прототип, но связывало бизнес-правила с транспортом и хранением данных.

## Решение

До подтверждения необходимости распределённой системы UnitAtlas остаётся модульным монолитом:

- `UnitAtlas.Domain` — сущности без EF/HTTP зависимостей;
- `UnitAtlas.Application` — правила use case и проекций;
- `UnitAtlas.Contracts` — входные и выходные контракты;
- `UnitAtlas.Infrastructure` — EF Core, PostgreSQL, миграции и bootstrap БД;
- `UnitAtlas.Api` — composition root и HTTP endpoints.

Зависимости направлены внутрь: API и Infrastructure используют Application/Domain, но Domain не знает о внешних слоях.

## Последствия

Плюс: доменные правила тестируются без БД, а схема развивается миграциями. Минус: текущие endpoints пока остаются в одном `Program.cs`; выделять каждый endpoint в отдельный класс до роста сложности не требуется.

## Rollback

Изменение не меняет публичные demo-маршруты. Откат выполняется возвратом PR и применением rollback SQL миграции в одноразовом окружении. Для production откат схемы должен быть отдельно проверен на сохранность данных.
